# iPhone app (plan, 2026-11-19)

Decision [0048](../decisions/0048-iphone-app.md); parents [0024](../decisions/0024-android-app.md), [0026](../decisions/0026-app-sign-in.md).
Phases, one builder package each (about 250 tool calls): **I1a** shared + server + Mac scripts, **I1b** Swift shell and
connect, **I1c** sign-in, sign-out, links, docs; then I2 audio, I3 downloads, I4 CarPlay, widget, TestFlight prep.
**Reused**: all of `android/shared`, the bundled pages and `strings.xml`, `/app/connect`, `POST|DELETE /api/v1/auth/token`,
`/healthz`, `shellFrom`/`shellLink` (already accept `ios`). **Extended**: `decide`, `Origin` URLs, `ApiPaths.shellUrl`,
the four window rules on the server. **Moved** (Android to shared, same behaviour): `Health`, `Swap`, `Me` and their
classification, the page-finished rules of `ConnectFlow`. **New**: `ios/`, `iosMain/RawUri.ios.kt`. **Replaced**: nothing.

## I1 invariants
1. Android behaves byte for byte as before: every change to shared code it uses is a move or a defaulted parameter; `:shared:jvmTest`, `lintRelease` and `assembleDebug` pass on Linux unchanged.
2. Linux never configures an iOS target (declared only when `os.name` starts with `Mac`); `verification-metadata.xml` only gains entries.
3. The token is only in the Keychain and in `Authorization` headers to `/api/v1/` of the pinned origin; never in a URL, a log, page script or `WKHTTPCookieStore`.
4. Native HTTP is an ephemeral `URLSession`: no cookies, no cache, redirects refused, answers read up to 4096 bytes.
5. A code is taken only from `/app/connect/done` on the exact origin, main frame, while a verifier is held; the load is cancelled; the verifier is cleared after one swap.
6. Bundled commands (`tsbundle://app/connect|link|...`) are obeyed only from the main frame of a bundled page (shared `decide`).
7. Browsers see no change: no template changes in I1; only `ts_shell=ios` requests change answers.
8. The app sends nothing anywhere except the typed origin (and its listed sign-in provider pages inside the window).

## Risks
- Xcode first-launch components are missing on the Mac (`-checkFirstLaunchStatus` exits 69); the operator runs `sudo xcodebuild -runFirstLaunch` once before I1a step 16.
- Guesses to confirm in I1a: the KGP simulator-test property name; whether the Kotlin/Native distribution comes through Gradle (then pinned) or from JetBrains' download site into `~/.konan` (then not pinned: record it in `docs/ios.md`); openrsync flag support; Kotlin 2.4.21 against Xcode 26.2 (a compatibility warning is acceptable).
- Only iOS 26 simulators exist, so iOS 17 behaviour is untested until a device or older runtime is available.
- Providers that refuse embedded web views (Google) cannot be used in the window, as on Android.
