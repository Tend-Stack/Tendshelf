## I2 invariants (all packages)
1. The token is only in the Keychain and in `Authorization` headers of native requests to `/api/v1/` of the pinned origin. AVPlayer sees only `tsmedia://m/<n>` handles; the loader fetches only URLs native code registered, and only while the current connection's origin equals the handle's.
2. Page to app: main frame only, `Origin.sameSource` of the frame's security origin, `ConnectState.Connected`, a `String` body, `TokenBucket(30)` before parsing, then `parseBridge`. App to page: only shared `encode*` output, through one delivery call. Nothing the page sent is logged; logs hold counts and kinds.
3. Browsers and the desktop shell get byte-identical pages; the Android window gets the same four scripts in the same order.
4. Android behaves as before: every shared change it uses is a move; `:shared:jvmTest`, `check-android.sh`, `make apk-debug` pass.
5. A place is written to SQLite before any send; rows of another device id are cleared before use; held rows are never sent; the shared `Outbox` is called on the main actor only.
6. A station saves no place, never seeks, has one speed and no chapter timer; an episode never gets the place question.
7. A running sleep timer that ends an item stops the queue; the chapter timer rests 1 s before the book's end.
8. The app makes no request to anyone but the typed origin.

## I2b: bridge, media loader, player, lock screen (builder, on the Mac through `make ios-sim`)
Decisions:
- **Bearer through `AVAssetResourceLoaderDelegate`** (0048 already chose it): the private `AVURLAssetHTTPHeaderFieldsKey` is not public API, and the token must not ride in a URL. Handles are opaque counters, so even the file ids stay out of AVFoundation's URL cache keys.
- **`AVQueuePlayer`, one item per playable file**, at most the current and the next queued; book time = `Position.bookPosition`. Not `AVMutableComposition`: it needs every file's header before the first sound, and remote assets in compositions seek poorly. A file the server lacks is skipped with the shared `skipSilence(silentRanges(files), ms)` rule, which is where Android's silence lands too. Small gaps between files are accepted.
- `AVAudioSession` `.playback`, mode `.spokenAudio` for books and episodes, `.default` for a station, policy `.longFormAudio`; `UIBackgroundModes` `audio`. Pitch `.timeDomain` (made for speech); speed is `defaultRate`, so a paused player keeps it.
- Lock screen by hand (`MPNowPlayingInfoCenter`), not `MPNowPlayingSession`: the shown time is book time, not item time.
- Theme: `theme #rrggbb` sets the web view's `underPageBackgroundColor` and the container background; `back`, `dl`, `tts`, `say`, `fav`, `quiet`, `autodl`, `pagekeys` are parsed and ignored (later phases or Android-only).
- `wake 1|0` sets `UIApplication.shared.isIdleTimerDisabled` through the shared `ReaderFeel` (`awake`, `front`, `reset`), as Android does with `FLAG_KEEP_SCREEN_ON`.
Kotlin from Swift: top-level functions are `<File>Kt.name(...)` (`BridgeProtocolKt.parseBridge(raw:)`), objects `.shared`, Long `Int64`, Int `Int32`, `List<Long>` `[KotlinLong]`; Kotlin constructors take every argument (no defaults).

## I2c: saving, resume, sleep, next book, sign-out (builder, on the Mac)
Decisions:
- The store is Swift over the system `SQLite3` module, conforming to the shared `OutboxStore` protocol (an `NSObject`). Not a Kotlin `iosMain` store: Swift's `SQLite3` is certain, the Kotlin side would need cinterop work for the same SQL.
- The store runs on the main actor (rows are small; one write each 10 s); network waits are `async` off it. A failed SQLite step cannot throw through the Kotlin protocol, so the store sets `lastWriteFailed` and the writer keeps the place in memory, as `ProgressWriter.kt:176-180`.
- While hidden, the place question waits for the page (no local notifications on iPhone): `diff.shown()` re-sends it on return.
- Background work that must finish (a flush after a pause, the end-of-book hand-off) runs inside `beginBackgroundTask`, the iPhone's analogue of Android's 30 s wake lock.
Steps:
1. ## Risks
- The endless radio stream through the resource loader is a guess (I2b step 11 proves it first).
- Starting the next book in the background after an item ends: iOS may suspend the app once sound stops; the hand-off keeps the session active inside a background task. Checked only on a device (operator).
- Seeks in VBR MP3 without a Xing header are approximate in AVFoundation (Android uses constant-bitrate seeking).
- Android `ProgressWriter.kt:78` drains the listened time and discards it before `record("pause")`, so the last stretch before a pause counts 0 ms on Android. The iPhone port does not repeat the extra drain; whether to fix Android is the orchestrator's call (a one-line change, not in I2).
- Only iOS 26 simulators: iOS 17 behaviour untested.
