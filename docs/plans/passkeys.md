# Passkeys (WebAuthn) beside passwords: builder plan (S10, decision 0041)

## 1. Invariants
- A passkey sign-in ends in the same `sessions` row and `ts_session` cookie as a password sign-in, through the same `ipLim`/`userLim`, the same disabled-account refusal, `auth.SafeNext`, and audit `auth.login` (detail `via: passkey`).
- The password form, OIDC and sign-in links are untouched; passkeys never replace them, and no change to them weakens or removes a passkey.
- A credential signs in only on the RP id (host name) it was made for, only when the client data's origin equals this request's origin, the challenge is a fresh, unused one this server issued, UV and UP are set, and the signature verifies.
- Challenges are 32 random bytes, single use, 5-minute life; only SHA-256 is stored. A register challenge is bound to the session that asked for it.
- Adding a passkey needs the current password, or (for an account with none) a session started in the last 15 minutes.
- A person sees and removes only their own passkeys (row id plus `user_id = session user` in SQL); an admin removes another person's only through `share.Can(ManageUsers)` plus `recheckManage` inside the transaction.
- No new module, no `NOTICES.md` row, CSP unchanged, no inline script, no `style=""`; JS only `static/js/passkey.js`, never minified.
- No passkey control is rendered in a shell window (`shellFrom(r) != ""`), on an IP-address host, or outside a secure context.

## 2. Decisions (reasons in docs/decisions/0041-passkeys.md)
1. Standard library only: new package `internal/auth/passkey` (crypto/ecdsa, crypto/rsa, crypto/ed25519, crypto/sha256, encoding/json). Same test as 0037.
2. Attestation conveyance `none`; any `fmt` accepted, `attStmt` decoded for well-formedness and never trusted or verified (no trust anchors to keep up to date).
3. Algorithms offered in order EdDSA (-8, Ed25519), ES256 (-7, P-256), RS256 (-257, 2048..4096-bit modulus). Anything else is `ErrAlgorithm`.
4. RP id = request host name, lowercased, port and trailing dot stripped; refused if empty, an IP (`netip.ParseAddr` ok) or not a DNS name. Origin = existing `requestOrigin(r)`. Each row stores its `rp_id`.
5. Secure context = `s.proxies.Secure(r)` or RP id is `localhost` / ends `.localhost`. Otherwise the account page explains and `/login` shows no button.
6. User verification `required` (the passkey is the whole sign-in). Resident key `required` (no username typed).
7. User handle: 32 random bytes in new column `users.passkey_handle`, made on first registration; never the user id or username.
8. Sign count: if stored or new count is non-zero and new <= stored, refuse, set `copied_at`, audit `passkey.copied`. Backup eligible (BE) must equal the stored value; BS is updated.
9. No browser-binding cookie: the challenge row is found by the hash of the challenge inside clientDataJSON; the finish POST needs the existing CSRF header (pre-login CSRF binding), which blocks login CSRF.
10. JSON ceremony endpoints are plain POSTs (not `/hx/`), CSRF in `X-CSRF-Token`; only the two `/login/passkey...` paths join the gate's public list.

## 3. Packages and ordered steps
### P1 Go: migration, verification, store, service (about 200 calls)
1. `internal/db/migrations/0044_passkeys.sql`: section 4 verbatim. `internal/db/db.go`: `SchemaVersion = 44`.
2. `internal/db/migration_passkeys_test.go`: `TestMigrationPasskeysFromPrevious` (openUpTo 43, users and sessions survive, handle NULL), `TestMigrationPasskeysFromEmpty` (checks, unique credential_id, unique handle, cascades from users and sessions, register-row CHECK).
3. `internal/auth/passkey/cbor.go`: `decodeCBOR(b []byte, depth int) (any, []byte, error)`: major types 0,1,2,3,4,5 and simple 20/21/22 only; refuse tags, floats, indefinite lengths, duplicate map keys, depth > 8, a length past the buffer; map keys int or text. Returns the rest so authData's COSE key and extensions are split.
4. `internal/auth/passkey/cose.go`: `parseCOSE(b) (publicKey, alg int, error)`; EC2 kty 2/alg -7/crv 1, x,y 32 bytes, `ecdsa.ParseUncompressedPublicKey(elliptic P256, 0x04||x||y)` (rejects off-curve); RSA kty 3/alg -257, n 2048..4096 bits, e odd 3..2^31-1; OKP kty 1/alg -8/crv 6, x 32 bytes. `verifySig(alg, pub, msg, sig)`: `ecdsa.VerifyASN1(sha256)`, `rsa.VerifyPKCS1v15(SHA256)`, `ed25519.Verify(msg)` (no prehash).
5. `internal/auth/passkey/authdata.go`: parse rpIdHash(32) flags(1) signCount(4 BE); AT -> aaguid(16) credIdLen(2) credId(<=1023) COSE key; ED -> one CBOR map, ignored; any byte left over is `ErrMalformed`. Flags UP 0x01, UV 0x04, BE 0x08, BS 0x10, AT 0x40, ED 0x80.
6. `internal/auth/passkey/verify.go`: types `RegistrationInput{ClientDataJSON, AttestationObject, Challenge []byte; Origin, RPID string; Transports []string}`, `Credential{ID, PublicKey []byte; Alg int; SignCount uint32; BackupEligible, BackedUp bool; AAGUID []byte; Transports []string}`, `AssertionInput{ClientDataJSON, AuthenticatorData, Signature, Challenge []byte; Origin, RPID string}`, `Assertion{SignCount uint32; BackedUp bool}`; funcs `VerifyRegistration(RegistrationInput) (Credential, error)`, `VerifyAssertion(AssertionInput, Credential) (Assertion, error)`, `ChallengeOf(clientDataJSON []byte) ([]byte, error)`, `NewChallenge() []byte`. Errors (also audit reasons): `ErrMalformed, ErrType, ErrChallenge, ErrOrigin, ErrCrossOrigin, ErrRPID, ErrPresence, ErrVerification, ErrBackupState, ErrAlgorithm, ErrKey, ErrSignature, ErrCounter`.
   Registration steps (WebAuthn L2 7.1): clientDataJSON valid UTF-8 JSON, at most 4 KiB; `type == "webauthn.create"`; `challenge` base64url (no padding) equals, constant time; `origin == Origin` exactly; `crossOrigin` absent or false; `tokenBinding` ignored; CBOR attestationObject with exactly `fmt` (text), `attStmt` (map), `authData` (bytes), nothing trailing; rpIdHash == SHA-256(RPID); UP set; UV set; BS set without BE refused; AT set; alg one of the three and the key valid; credential id 16..1023 bytes; attStmt ignored; counter returned.
   Assertion steps (7.2): same clientData checks with `type == "webauthn.get"`; authData has no AT; rpIdHash == SHA-256(RPID); UP; UV; BE == stored BE, BS without BE refused; signature over `authData || SHA-256(clientDataJSON)`; counter rule of decision 8 returns `ErrCounter`.
7. `internal/auth/passkey/passkey_test.go`: a software authenticator in the test file (`type softAuth struct{alg int; key crypto.Signer; credID []byte; count uint32; flags byte}` with a test-only CBOR encoder) for all three algorithms. Tests: `TestRegisterEachAlgorithm`, `TestRegisterRefusals` (table: wrong type, challenge, origin incl. port and scheme, crossOrigin true, rpIdHash, no UP, no UV, BS without BE, no AT, unknown alg, off-curve point, RSA 1024, trailing bytes, duplicate map key, tag, indefinite length, depth 9), `TestAssertEachAlgorithm`, `TestAssertRefusals` (same plus bad signature, AT set, BE changed), `TestCounter` (0/0 ok, 5->6 ok, 6->6 and 6->2 refused, 0->3 ok), `FuzzDecodeCBOR`, `FuzzVerifyRegistration` (never panics).
8. `internal/auth/passkeys.go` (Service methods, same package as service.go). Constants `passkeyTTL = 5*time.Minute`, `passkeyStartMax = 30` (per address per `limitWindow`, new limiter `pkStart` in NewService), `passkeyOpenMax = 500`, `passkeyPerUser = 20`, `passkeyFresh = 15*time.Minute`.
   - `PasskeySignInBegin(ctx, rpID, origin string, ip) ([]byte challenge, error)`: pkStart.Allow, purge expired, refuse at 500 open (`ErrPasskeyBusy`), insert purpose `signin`.
   - `PasskeySignIn(ctx, in PasskeyAssertion{RawID, UserHandle, ClientDataJSON, AuthenticatorData, Signature []byte}, rpID, origin, ip, ua, prev *Session) (Login, error)`: `ipLim.Allow` before any read; `ChallengeOf` -> hash -> consume row (DELETE ...    - `Passkeys(ctx, userID) ([]PasskeyRow, error)` (id, name, created_at, last_used_at, backup_eligible, copied_at, rp_id), newest first.

## 4. Data, migration, routes
`0044_passkeys.sql`:
```
ALTER TABLE users ADD COLUMN passkey_handle BLOB CHECK (passkey_handle IS NULL OR length(passkey_handle) = 32);
CREATE UNIQUE INDEX users_passkey_handle ON users(passkey_handle) WHERE passkey_handle IS NOT NULL;
CREATE TABLE passkeys (id TEXT PRIMARY KEY, user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  credential_id BLOB NOT NULL UNIQUE CHECK (length(credential_id) BETWEEN 16 AND 1023),
  rp_id TEXT NOT NULL CHECK (length(rp_id) BETWEEN 1 AND 253), public_key BLOB NOT NULL CHECK (length(public_key) BETWEEN 32 AND 1024),
  alg INTEGER NOT NULL CHECK (alg IN (-7, -8, -257)), sign_count INTEGER NOT NULL DEFAULT 0 CHECK (sign_count BETWEEN 0 AND 4294967295),
  backup_eligible INTEGER NOT NULL CHECK (backup_eligible IN (0,1)), backed_up INTEGER NOT NULL CHECK (backed_up IN (0,1)),
  transports TEXT NOT NULL DEFAULT '' CHECK (length(transports) <= 128), aaguid BLOB CHECK (aaguid IS NULL OR length(aaguid) = 16),
  name TEXT NOT NULL CHECK (length(name) BETWEEN 1 AND 256), created_at INTEGER NOT NULL, last_used_at INTEGER, copied_at INTEGER) STRICT;
CREATE INDEX passkeys_user ON passkeys(user_id);
CREATE TABLE passkey_ceremonies (challenge_hash BLOB PRIMARY KEY CHECK (length(challenge_hash) = 32),
  purpose TEXT NOT NULL CHECK (purpose IN ('signin','register')), rp_id TEXT NOT NULL, origin TEXT NOT NULL,
  user_id TEXT REFERENCES users(id) ON DELETE CASCADE, session_hash BLOB REFERENCES sessions(token_hash) ON DELETE CASCADE,
  created_at INTEGER NOT NULL, expires_at INTEGER NOT NULL, addr_key TEXT NOT NULL DEFAULT '',
  CHECK ((purpose = 'register') = (user_id IS NOT NULL AND session_hash IS NOT NULL))) STRICT, WITHOUT ROWID;
CREATE INDEX passkey_ceremonies_expires ON passkey_ceremonies(expires_at);
```
(name: 64 runes is enforced in Go; 256 bytes in SQL.) Transports: comma-joined, only `usb,nfc,ble,internal,hybrid,smart-card`.
