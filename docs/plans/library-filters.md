# Plan: Library filter header (Filter menu, Show + Sort, Category)

Operator request 2026-11-03; decision 0008 below (the orchestrator adds the file). One builder package.
Do not touch `routes_book.go`, `pages/book.templ`, `routes_jobs.go`, `shell.js`, any JS, `bundle.css`, Home.

## 1. Invariants
- Every filter, sort, view and page position stays an address; every control works without JS (`<details>` + links, GET form).
- `add=<kind>` is never carried into any address the page builds except the Filter menu's own kind links (enforced once, in `href`).
- A kind chip appears in the kinds row only when its value is set or it is `q.Add`; at most one menu renders `open`.
- Title typing and paging still swap only `#library-results`; `id="fb-title"` stays outside it.
- Grants: Category lists `s.lib.Genres` (already scoped); facets unchanged; nothing new is fetched unfiltered.
- No new JS, no inline style/script, no `hx-on`/`js:`; 44 px targets; 13 px minimum; four themes; no horizontal overflow at 390/768/1024/1440.
- `pages-library.css` stays under 3 KB gzip (today 1960 B with `gzip -c`).

## 2. Decisions
- D1 One `add` value, written only by the Filter menu's kind links: the URL stays shareable (opens that menu) and an empty kind dies on the next navigation of any kind, so no state lingers. `href` zeroes `Add` before `mod`, so only a mod that sets it writes it.
- D2 Retire the "Filter and sort" sheet (`?sheet=filters`, `LibraryFilterSheet`, the radio form): the chip menus already work with no JS at every width, so the sheet is a duplicate. `?sheet=filters` is now an ignored param (200, normal page).
- D3 Title field is visible at all widths (today only >=1280); the sort `<select>`, `.ts-lib-sort` button and "More filters" chip go.
- D4 Layout: row A `.ts-lib-controls` = title form, Filter chip, Show chip, Grid/List (right). Row B `.ts-lib-filters` = kind chips, rendered only when non-empty. Below 768 the title form takes a full line and the Grid/List words are visually hidden (icons stay, accessible names stay).
- D5 Show menu holds two titled groups, "Show" then "Sort by". Chip: `Show`, `Show: Unfinished`, plus ` · By title|By author|By length` when sort is not the default. `is-on` only for the show filter (sort is not a filter).
- D6 Category = one multi-select menu: options are toggle links (existing `toggle`), "Any category" drops all genres; at 5 chosen the unchosen options render disabled (no dead links).
- D7 Popover anchor: Filter and Show open left-anchored (they sit left of the toggle at every width); a kind chip at row-B index >= 2 gets `End`. If the visual inside-window check fails, adjust only this rule and report it.
- D8 Focus: the opened menu's `<summary>` gets `autofocus`; htmx 4 focuses `[autofocus]` after a swap (verified in `vendor/htmx-4.0.0.min.js`), the browser does on a plain load.

## Draft decision 0008: Library filter header
Status: accepted 2026-11-03 (operator). Overrides `design-system/components/Chip/README.md` and the Library boards where they differ.
- The Library header has one "Filter" chip menu listing the kinds (Author, Narrator, Series, Category, Length). Choosing a kind adds that kind's chip menu, open; only kinds in use show. Each active chip shows its value and an "Any ..." item clears it.
- Genres are one "Category" menu (multi-select, at most five), not a chip per genre.
- "Show" holds the show states and "Sort by"; there is no separate sort control.
- The "Filter and sort" sheet and "More filters" are retired; the same chip menus serve phone, tablet and desktop, without JavaScript.
- `add=<kind>` opens a kind for one page view and is never carried forward.
